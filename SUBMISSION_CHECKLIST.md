# AHGV Buildventure — Submission Checklist

## 1. Hosted working application
- [ ] Live URL opens.
- [ ] Registration and login tested successfully.
- [ ] Main features tested end-to-end.
- [ ] Backend health/database connectivity checked.
- [ ] Known errors fixed or disclosed.

## 2. GitHub source repository
- [ ] Use a repository owned/authorized by the team.
- [ ] Push frontend, backend, migrations, README and docs.
- [ ] Ensure `.env`, keys, passwords and database credentials are excluded.
- [ ] Check repository access matches event rules.

## 3. Architecture diagram
- [ ] Include `ARCHITECTURE.md`.
- [ ] Export the Mermaid diagram to PNG/PDF if the portal requires a separate image.

## 4. README/setup documentation
- [ ] Verify commands against package scripts.
- [ ] Explain database setup and migrations.
- [ ] Document variable names, never secret values.

## 5. API documentation
- [ ] Verify exact methods/routes against source.
- [ ] Document inputs, responses, authentication and status codes.
- [ ] Test the documented examples.

## 6. Sample dataset
- [ ] Upload synthetic demo data only.
- [ ] Explain file format and fields.
- [ ] Do not upload real user/student data.

## 7. Evaluation/testing
- [ ] Enter actual results in the test table.
- [ ] Add screenshots/logs with secrets removed.
- [ ] State limitations honestly.

## 8. Demo video
- [ ] Record a 2–4 minute walkthrough.
- [ ] Show only working features.
- [ ] Hide secrets and private dashboards.

## 9. Deployment instructions
- [ ] Include frontend, backend and database deployment steps.
- [ ] Verify all live URLs before submission.

Remove placeholder or unverified claims before final upload.
